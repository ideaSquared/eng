# Cloudflare app standards

Applies to repos of type `cloudflare-app` (see [README.md](README.md)), on top of [common.md](common.md): Hono API
Workers, frontends served by Workers static assets, D1 with Drizzle, R2, Queues and Cron.

## Layout and Wrangler config

**CF-01** · MUST · Every deployable Worker has its own `wrangler.jsonc` beside its `package.json` (not
`wrangler.toml` or `wrangler.json`). [C1]
Check: `git ls-files '*wrangler.toml' '*wrangler.json'` is empty; each Worker directory has `wrangler.jsonc`.

**CF-02** · MUST · Frontends are Workers with static assets: `assets.directory` points at the build output, single-page
apps set `assets.not_found_handling: "single-page-application"`, and no config has `pages_build_output_dir`. [C2][C3]
Check: `grep -l pages_build_output_dir $(git ls-files '*wrangler.jsonc')` is empty; frontend configs have `assets.directory`.

**CF-03** · MUST · `compatibility_date` is set in every `wrangler.jsonc` and is no more than 180 days old; it is
moved forward in its own PR after reading the compatibility-flags changelog and running the tests. [C4]
Check: `jq -r .compatibility_date` (after stripping comments) is within 180 days of today.

**CF-04** · MUST · Every Worker with a `main` script sets `observability.enabled: true`. [C1]
Check: `.observability.enabled == true` in each `wrangler.jsonc` that has `main`.

**CF-05** · SHOULD · High-traffic Workers set `observability.head_sampling_rate` explicitly (below 1 when log volume
needs it). [C1]
Check: key present where request volume warrants; otherwise defaults to 1.

## Environments

A **public-facing** repo serves customers or the public (creatrgrid, pairflix). An **internal tool** is used only
by the ideaSquared team, not by customers or the public (agent-idea, ideasquared-bot); the README repo table marks
them. A staging environment is MUST for public-facing repos and SHOULD for internal tools.

**CF-06** · MUST (public-facing) / SHOULD (internal tool) · Each Worker defines `env.staging` with its own `name` (suffix `-staging`) and repeats every
non-inheritable key (`vars`, `d1_databases`, `r2_buckets`, `kv_namespaces`, `durable_objects`, `queues`, `services`)
with staging resources, so staging never touches production data. [C1]
Check: `.env.staging.name` ends in `-staging`; each top-level binding key also exists under `env.staging` with a
different resource id/name.

**CF-07** · MUST (public-facing) / SHOULD (internal tool) · `ship.yaml` lists `staging` and `production`, with `production.requires: [staging]`, and every
Worker component sets `wranglerEnv` for staging. [C10]
Check: `yq '.environments.production.requires' ship.yaml` contains `staging`.

## Secrets and config

**CF-08** · MUST · `vars` hold no secrets; secrets are set with `wrangler secret put` (or shipper's build hook), and
local values live in a git-ignored `.dev.vars` beside the config with a committed `.dev.vars.example`. [C5]
Check: no key in any `vars` block matches `/(SECRET|TOKEN|KEY|PASSWORD)/i` with a non-empty value;
`test -f .dev.vars.example` beside each config that has secrets.

**CF-09** · SHOULD · Required secret names are declared in the `secrets` config property so a deploy fails when one
is missing; optional ones are typed in an interface extending `Env`. [C5]
Check: `wrangler.jsonc` has a `secrets` key listing every secret named in `.dev.vars.example` that the Worker needs.

## Bindings and types

**CF-10** · MUST · Binding types come from `wrangler types`: `worker-configuration.d.ts` is committed beside each
Worker config, listed in that tsconfig's `compilerOptions.types`, regenerated by a `cf-typegen` script, and CI fails
when it is stale; `@cloudflare/workers-types` is not used. [C6]
Check: `test -f worker-configuration.d.ts`; `jq -e '.scripts["cf-typegen"]'`; CI runs `wrangler types --check` (or
`wrangler types && git diff --exit-code worker-configuration.d.ts`).

## D1 and Drizzle

**CF-11** · MUST · The schema lives in Drizzle (`packages/db/src/schema.ts` or `src/db/schema.ts`), migrations are
generated with `drizzle-kit generate` into the directory named by the D1 binding's `migrations_dir`, and
`migrations/meta/` is committed. [C7][C8]
Check: `d1_databases[].migrations_dir` exists and contains `meta/_journal.json` tracked by git.

**CF-12** · MUST · A shipped migration is never edited or deleted; CI fails a PR that modifies or removes a file under
the migrations directory that exists on the default branch. [C7]
Check: `ci.yml` runs `git diff --diff-filter=MDR --name-only origin/<default>...HEAD -- <migrations_dir>` and fails
on output.

**CF-13** · MUST · Migrations are applied by the deploy, before the Worker code, staging first: the API component in
`ship.yaml` sets `migrations: { d1: <BINDING> }`, and the top-level `migrations:` lists the migration directories so
`ship diff` shows them. [C10]
Check: `yq '.components[].migrations.d1' ship.yaml` is set for the Worker that owns the binding; `yq .migrations ship.yaml`.

**CF-14** · MUST · Migrations are backward compatible with the previous Worker version (expand, then contract in a
later release), because a Worker rollback does not undo a migration, and the repo's runbook documents restoring D1
with Time Travel. [C9][C10]
Check: `grep -rl 'd1 time-travel restore' docs README.md` is non-empty.

## Testing

**CF-15** · MUST · Worker tests run inside workerd through Cloudflare's Vitest integration with real local bindings:
`@cloudflare/vitest-plugin` (`cloudflareTest()` in `vitest.config.ts`) for new and migrated repos, or
`@cloudflare/vitest-pool-workers` until migrated; D1 tests apply the real migrations. [C11]
Check: the Worker's `vitest.config.*` imports `@cloudflare/vitest-plugin` or `@cloudflare/vitest-pool-workers`.

**CF-16** · SHOULD · Repos still on `@cloudflare/vitest-pool-workers` migrate to `@cloudflare/vitest-plugin`. [C11]
Check: no `@cloudflare/vitest-pool-workers` in any `package.json`.

**CF-17** · MUST · CI builds each Worker as a deploy would without deploying (`wrangler deploy --dry-run`, with
`--env staging` where defined).
Check: `grep -rn 'wrangler deploy --dry-run' .github/workflows package.json` covers every Worker.

## Deploy and health

**CF-18** · MUST · Deploys go through shipper: `ship.yaml` at the root, the deploy job calls
`ideaSquared/shipper/.github/workflows/deploy.yml@v1`, a `ship-rollback.yml` exists, and no workflow runs
`wrangler deploy` or `wrangler pages deploy` directly. [C10]
Check: `test -f ship.yaml`; `grep -rn 'shipper/.github/workflows/deploy.yml@v1' .github/workflows`;
`grep -rnE 'wrangler (pages )?deploy( |$)' .github/workflows | grep -v dry-run` is empty.

**CF-19** · MUST · Every API Worker serves an unauthenticated `GET /health` (liveness, 200 JSON) and, when it has a
D1 binding, `GET /health/ready` that queries D1; its `ship.yaml` component `health` points at the readiness URL so a
bad deploy rolls back. [C10]
Check: `yq '.components[] | select(.type=="cloudflare-worker") | .health' ship.yaml` is set for every API Worker;
`curl -fsS <url>` returns 200.

**CF-20** · SHOULD · Frontend Worker components in `ship.yaml` also set `health` (the site's `/`) or a `smoke` URL.
[C10]
Check: every component has `health` or `smoke`.

## Rate limiting, CORS and caching

**CF-21** · MUST · Unauthenticated endpoints that cost money or protect accounts (sign-in, sign-up, password reset,
invitations, unsigned webhooks) are rate limited, either with the Workers `ratelimits` binding (approximate, per
location) or with a D1 / Durable Object counter where an exact limit matters. [C12][C13]
Check: the routes for those endpoints use a rate-limit middleware, or `wrangler.jsonc` has `ratelimits` used by them.

**CF-22** · MUST · CORS uses an explicit origin allowlist from config (e.g. `ALLOWED_ORIGINS`), never `*` together
with credentials. [C14]
Check: `grep -rn "origin: '\*'" src` is empty; the `cors()` origin reads the allowlist.

**CF-23** · MUST · Every frontend sends security headers from `_headers` in its assets directory (or from the Worker's
`Response` when `run_worker_first` is on): `Strict-Transport-Security`, `Content-Security-Policy` (with
`frame-ancestors`), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`. [C3][C14]
Check: `curl -sI https://<site>/` shows the four headers.

**CF-24** · SHOULD · Fingerprinted build assets get `Cache-Control: public, max-age=31536000, immutable` via
`_headers` (`/assets/*`); HTML keeps the default revalidating cache; authenticated API responses send
`Cache-Control: no-store`. [C3]
Check: `curl -sI https://<site>/assets/<file>` shows `immutable`; an authenticated API call shows `no-store`.

**CF-25** · SHOULD · Production Workers serve from a custom domain (`routes` with `custom_domain: true`) and set
`workers_dev: false` once one exists. [C1]
Check: `.routes[].custom_domain == true` and `.workers_dev == false` at top level.
